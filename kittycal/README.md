# Kittycal

A free, private cycle tracker. Everything Flo's period tracker does, none of the
network.

Your data lives in your browser's local database on your own device. There is no
account, no server, no analytics, and no subscription. The app makes **no
outbound network requests at all** — the fonts and every image are part of the
app itself, and a Content Security Policy enforces it rather than us just
promising it.

## Why

Flo is the obvious choice and the wrong one to hand this data to. In 2021 the
FTC charged Flo Health with promising privacy while sending menstruation and
pregnancy status to Facebook's and Google's analytics SDKs; in a 2025 class
action Google and Flo settled for a combined $56M, and a jury found Meta liable
under California's wiretap statute. On top of
that, the genuinely useful parts — cycle reports, symptom pattern analysis, a
health report you can hand a doctor — sit behind a $49.99/year paywall.

None of that is necessary. A cycle tracker is a calendar, some arithmetic and a
list of symptoms. It does not need a server, and it should not want one.

## What it does

- **Cycle predictions** — next period, ovulation, fertile window, each with a
  stated confidence level and a plain-language account of where the number came
  from. Lateness is a first-class state, not a silently redrawn forecast.
- **Calendar** — logged periods, predicted periods, fertile window, ovulation.
  Tap or drag to mark period days, including retroactively; filling in an old
  period re-shapes every prediction after it.
- **A diary of ~110 things** across 12 categories — flow, mood, symptoms,
  discharge, sex, sex drive, activity, life events, pregnancy and ovulation
  tests, BBT, weight, sleep, steps, water, birth control, notes — plus unlimited
  custom symptoms.
- **Insights** — cycle and period length against the ACOG typical range,
  regularity, BBT charting with thermal-shift detection, weight and sleep
  trends, and symptom patterns showing *where in the cycle* something lands
  ("cramps, 10 of 10 cycles, most often on day 1 and 2").
- **A printable report for a doctor** — six months of history as plain tables.
  Every print dialogue offers "Save as PDF".
- **14 themes**, each in light and dark, with original mascot art — or use your
  own photos.
- **Passcode lock** — 4 digits, stored only as a PBKDF2 hash.
- **Reminders** for period-soon, late, fertile window, birth control and logging.
- **Export and erase** — a complete, readable JSON export, and a real delete.
- Fertility estimates are hidden when you're on hormonal birth control, because
  ovulation isn't happening and a guess dressed up as a prediction is worse than
  nothing.

### Not built, deliberately

Flo's anonymous forum and AI health assistant both need a server, so they're
out. Its PCOS/endometriosis symptom checker is medical screening, and this
doesn't ship a diagnosis engine — instead there's an honest "worth mentioning to
a doctor" prompt using the cycle-length and period-length ranges ACOG publishes,
framed as a reason to ask a professional rather than as a finding. Apple Health
and Watch sync aren't available to a web app.

Reminders are the one place the no-server design has a visible cost. Flo can
notify you out of the blue because Flo runs a server that pushes to your phone —
and that server necessarily knows your cycle. Kittycal's reminders fire when you
next open the app on the day they're due, and the settings screen says so rather
than promising delivery that won't arrive.

**Kittycal is not contraception and not medical advice.** Predicted periods,
fertile windows and ovulation days are estimates calculated from your own logs.

## Running it

It's a static site with no build step and no dependencies. Open it with any
static server:

```sh
python3 -m http.server 8080     # then visit http://127.0.0.1:8080
```

ES modules don't load over `file://`, so it does need to be served rather than
double-clicked. Deployed to GitHub Pages or any static host, it installs to a
phone home screen as a PWA and works fully offline afterwards.

## Development

No `npm install` — there are no dependencies. The `package.json` exists only to
mark the directory as ESM and to hold these scripts:

```sh
npm test           # 97 unit tests, node's built-in runner
npm run typecheck  # JSDoc types via tsc --noEmit; no build, no emit
npm run serve      # static server on :8080
```

Two checks need a real browser, so they live outside the unit suite. Start the
server first:

```sh
npm run serve &
npm run test:contrast   # every colour pair, 14 themes x 2 modes
npm run test:network    # asserts zero off-origin requests, and offline works
```

`test:contrast` exists because the palette is generated by OKLCH expressions
that only a CSS engine can resolve; it measures rendered pixels and checks them
against WCAG 1.4.3 (4.5:1 for text) and 1.4.11 (3:1 for control boundaries).

`test:network` is the privacy claim made falsifiable. It walks every view,
opens the logging sheet, cycles themes, and fails if a single request leaves the
app's own origin — then cuts the network and confirms the app still loads and
renders. It should report `all network checks pass`.

### How it's put together

```
index.html            app shell, CSP, pre-paint theme script
css/tokens.css        the design system — every colour derives from two numbers
css/themes.css        14 themes, each a hue and a chroma
js/domain/            pure functions: cycles, predictions, phases, ACOG ranges
js/storage/           IndexedDB wrapper, repositories, export/import
js/state/store.js     one store, plain actions, debounced persistence
js/views/             one module per screen
js/ui/                ring, sheets, toasts, particles, mascots, theming
test/                 unit tests for the domain and storage layers
```

Two ideas carry most of the weight:

**Nothing about cycles is stored.** The only source of truth is the set of days
you've marked as bleeding. Cycles, phases, averages and forecasts are all derived
from that set, every time. That's what makes retroactive edits work — filling in
a period from three months ago automatically re-shapes every prediction after it.

**A theme is two numbers.** Each theme sets a hue and a chroma, and every colour
is derived from them in OKLCH at a fixed lightness. Because OKLCH lightness is
perceptually uniform, pinning it per token means every theme hits the same
contrast ratios by construction — there's no per-theme accessibility audit, and
adding a fifteenth theme is two lines.

### Design rules

Cute is the opposite of clinical, not the opposite of serious. Four rules the
code actually follows:

1. Cute lives in the chrome; data lives in a restrained zone. Anything inside
   `.data-zone` drops to thinner borders, smaller radii, tabular numerals and no
   decorative motion.
2. The mascot reacts to the act of logging, never to what was logged. There is no
   sad face at a heavy day — that's how you teach someone to stop recording bad
   days.
3. Alerts are theme-immune. A warning keeps fixed contrast, a fixed icon and a
   fixed shape across all 14 themes. A pastel error is an unread error.
4. Ship the exit. The **Plain** theme has no patterns and no motion, for the day
   you show this screen to a doctor. Being able to turn the cute all the way off
   is what makes it safe to turn all the way up by default.

## Artwork

The built-in mascots are original artwork: charm emblems built from generic
shapes — a bow, a cloud, a star, a paw, a lightning bolt — in each theme's
palette. To use your own pictures instead, go to Settings → Themes → *use your
own picture*, or see [`assets/mascots/README.md`](assets/mascots/README.md).
